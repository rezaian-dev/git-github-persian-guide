5:T6788,<p class="lead">خانهٔ روزانهٔ Git در VS Code پنل Source Control است. میانبر ثابت این کتاب Ctrl+Shift+G است. اینجا هر کلیک را به ترتیب می‌نویسیم و برای هر تفاوت («چرا مال من این‌طور است؟») دلیل دقیق می‌آید.</p>
  <h2><span class="hx"><span class="hx-t">🎯 اهداف یادگیری</span></span></h2>
<ul>
<li>پنل را با کلیک مشخص باز کنی و بدانی بعد از آن باید چه ببینی</li>
<li>اگر دکمه یا لیست تو با عکس کتاب یکی نبود، در همان لحظه علت را بدانی</li>
<li>یک فایل را از Save تا Commit، کلیک‌به‌کلیک، تمام کنی</li>
<li>Stage، Unstage، Discard و Stage Selected Ranges را بدون حدس بزنی</li>
</ul>

<h2><span class="hx"><span class="hx-t">⌨️ باز کردن پنل — سه کلیک معادل، یکی کافی است</span></span></h2>
<p class="keep-next">یکی از این سه را بزن؛ هر سه باید <strong>همان ستون چپ</strong> را باز کنند:</p>
<ol>
<li>صفحه کلید: <code>Ctrl+Shift+G</code> (ویندوز، لینوکس، مک)</li>
<li>ماوس: در نوار باریک چپ (Activity Bar) روی آیکون شاخه/Git کلیک کن — در عکس کتاب شمارهٔ ۱</li>
<li>اگر هیچ‌کدام کار نکرد: <code>Ctrl+Shift+P</code> → تایپ کن <code>View: Show Source Control</code> → Enter</li>
</ol>
<p><strong>بعد از باز شدن باید ببینی:</strong> ستون سمت چپ با عنوان Source Control. ادیتور سمت راست سر جایش می‌ماند.</p>

</table></div><h2><span class="hx"><span class="hx-t">🧭 آناتومی — بعد از باز شدن، این چهار نقطه را لمس کن</span></span></h2>
<div class="shot zoom">
<img src="/git-github-persian-guide/book/figures/vscode-scm-anatomy.png" alt="آناتومی نزدیک پنل Source Control"/>
<p class="figcap">شکل ۹ — برش نزدیک. شماره‌ها را با فهرست زیر تطبیق بده. دکمهٔ آبی اینجا Sync است نه Commit؛ برای تو ممکن است برعکس باشد.</p>
</div>
<ol class="legend">
<li><strong>کلیک روی آیکون Git</strong> در Activity Bar. اگر روی آیکون <em>عدد</em> بود یعنی فایل تغییرکرده داری. اگر عدد نبود، یا Working Tree تمیز است یا نشان روی آیکون دیگری است (در عکس کامل کتاب، نشان آبی روی Extensions است نه Git — این باگ نیست).</li>
<li><strong>عنوان Source Control</strong> و سه‌نقطهٔ <code>···</code> بالا-راست. یک کلیک روی <code>···</code> منوی Fetch / Pull / Push / Stash را باز می‌کند (فصل ۱۱).</li>
<li><strong>یک کلیک داخل جعبهٔ Message</strong> — مکان‌نما باید چشمک بزند. این‌جا متن کامیت را می‌نویسی. <code>Ctrl+Enter</code> فقط وقتی کار می‌کند که فوکوس همین جعبه باشد.</li>
<li><strong>دکمهٔ بزرگ زیر جعبه</strong> — برچسبش <em>ثابت نیست</em>. VS Code بر اساس وضعیت مخزن یکی از این‌ها را می‌نویسد: <strong>Initialize Repository</strong>، <strong>Publish Branch</strong>، <strong>Commit</strong>، <strong>Sync Changes</strong>، یا <strong>Commit (merge)</strong>.</li>
</ol>
<p class="keep-next">پایین همان ستون، بدون عوض کردن پنل:</p>
<ul>
<li><strong>Graph</strong> — یک کلیک روی <code>&gt;</code> یا روی کلمهٔ Graph. اگر نبود، VS Code را به‌روز کن یا Palette → <code>Git: View History</code>.</li>
<li class="keep-next"><strong>نوار وضعیت پایین-چپ پنجره</strong> (نه داخل ستون): نام شاخه. <strong>یک کلیک</strong> روی نام شاخه = فهرست عوض کردن شاخه.</li>
</ul>
<div class="shot zoom">
<img src="/git-github-persian-guide/book/figures/vscode-scm-status-zoom.png" alt="نوار وضعیت Git در VS Code"/>
<p class="figcap">شکل ۹ب — یک کلیک روی main. عدد ↓ و ↑ مال این مخزن است؛ مال تو ۰ و ۰ هم طبیعی است.</p>
</div>
<p><strong>اگر نوار وضعیت شاخه نشان نمی‌دهد:</strong> یا پوشه Git ندارد، یا Git پیدا نشده. اول همان جدول «اگر مال تو این‌طور نیست» را بالا ببین.</p>
<h2><span class="hx"><span class="hx-t">😶 دکمهٔ بزرگ زیر Message — از روی برچسب بفهم کجایی</span></span></h2>
<p>VS Code یک دکمهٔ اصلی دارد. برچسب را بخوان؛ حدس نزن.</p>
<h3><span class="hx"><span class="hx-t">حالت ۱ — نوشته Initialize Repository / Publish to GitHub</span></span></h3>
<p class="keep-next">یعنی پوشه‌ای که <strong>Open Folder</strong> کرده‌ای فایل <code>.git</code> ندارد.</p>
<div class="shot zoom">
<img src="/git-github-persian-guide/book/figures/vscode-scm-init-zoom.png" alt="Initialize Repository در Source Control"/>
<p class="figcap">شکل ۹پ — فقط وقتی `.git` نیست این دو دکمه را می‌بینی.</p>
</div>
<p><strong>کلیک‌ها:</strong></p>
<ol>
<li><code>File → Open Folder</code> — پوشهٔ خود پروژه را انتخاب کن، نه درایو و نه پوشهٔ والد.</li>
<li><code>Ctrl+Shift+G</code>.</li>
<li><strong>یک کلیک</strong> روی <strong>Initialize Repository</strong>. معادل <code>git init</code>. بعد از کلیک باید جعبهٔ Message ظاهر شود و اگر فایلی باشد، لیست Changes پر شود.</li>
<li>همان لحظه فایل <code>.gitignore</code> بساز (<code>Ctrl+N</code>، ذخیره با همین نام) تا <code>node_modules</code> در Changes نیاید.</li>
<li><strong>Publish to GitHub</strong> را فقط اگر می‌خواهی ریپو روی GitHub ساخته شود بزن. اگر بزنی و وارد حساب نباشی، پنجرهٔ ورود مرورگر باز می‌شود — این خطا نیست.</li>
</ol>
<p><strong>اگر بعد از Initialize هنوز همان دو دکمه را می‌بینی:</strong> پوشهٔ اشتباه باز است. در Explorer باید <code>.git</code> را (گاهی مخفی) ببینی. <code>File → Open Folder</code> را تکرار کن.</p>
<p><strong>اگر Publish خاکستری است یا خطا می‌دهد:</strong> Accounts پایین Activity Bar → Sign in to GitHub. بدون ورود، Publish کار نمی‌کند؛ Initialize کار می‌کند.</p>
<h3><span class="hx"><span class="hx-t">حالت ۲ — نوشته Sync Changes (شاید با عدد ↓ یا ↑)</span></span></h3>
<p>یعنی مخزن هست، <strong>فایل ذخیره‌شدهٔ تغییرکرده برای کامیت نداری</strong>، ولی با <code>origin</code> هم‌تراز نیستی.</p>
<ul>
<li><code>۱۵↓</code> = روی سرور ۱۵ کامیت هست که تو نداری → Sync تقریباً <code>pull</code> است.</li>
<li><code>↑۳</code> = تو ۳ کامیت داری که سرور ندارد → Sync تقریباً <code>push</code> است.</li>
<li>هر دو = واگرایی؛ Sync ممکن است merge بسازد.</li>
</ul>
<p>لیست Changes خالی در این حالت <strong>موفقیت</strong> است (<code>nothing to commit, working tree clean</code>)، نه اینکه Git خراب باشد.</p>
<p><strong>اگر Sync را زدی و از تو تأیید خواست:</strong> تنظیم <code>git.confirmSync</code> روشن است — Yes بگو یا در Settings خاموشش کن.</p>
<p><strong>اگر Sync خطا داد (rejected / diverged):</strong> فصل ۱۱ — اول Fetch، بعد Pull یا Pull (Rebase). Force نزن.</p>
<h3><span class="hx"><span class="hx-t">حالت ۳ — نوشته Commit (یا Commit با فلش ▾)</span></span></h3>
<p>یعنی حداقل یک فایل در Changes یا Staged هست.</p>
<p><strong>اگر تو Commit می‌بینی و کتاب Sync:</strong> تو فایل ذخیره‌نشده یا تغییرکرده داری؛ کتاب در آن عکس Working Tree تمیز نشان می‌دهد. هر دو درست‌اند.</p>
<h2><span class="hx"><span class="hx-t">✍️ مسیر کامل کامیت — کلیک به کلیک</span></span></h2>
<p class="keep-next">هدف: یک فایل را عوض کنی و در تاریخچه ثبت شود.</p>
<div class="shot zoom">
<img src="/git-github-persian-guide/book/figures/vscode-scm-commit-zoom.png" alt="کامیت و diff در Source Control"/>
<p class="figcap">شکل ۱۰ — بعد از مرحلهٔ ۴ باید چیزی شبیه این ببینی: پیام، فایل‌ها با M/U، diff سبز/قرمز.</p>
</div>
<ol>
<li>
<p><strong>فایل را در ادیتور عوض کن</strong> و <code>Ctrl+S</code> بزن.<br />
<strong>باید ببینی:</strong> روی آیکون Git عدد می‌آید؛ فایل در Changes ظاهر می‌شود.<br />
<strong>اگر نیامد:</strong> Save نشده، یا فایل داخل <code>.gitignore</code> است، یا پوشهٔ دیگری Open است.</p>
</li>
<li>
<p><strong><code>Ctrl+Shift+G</code>.</strong><br />
<strong>باید ببینی:</strong> نام فایل + حرف <code>M</code> یا <code>U</code>.</p>
</li>
<li>
<p><strong>یک کلیک روی نام فایل در Changes.</strong><br />
<strong>باید ببینی:</strong> سمت راست، diff. خط قرمز = حذف، سبز = اضافه.<br />
<strong>اگر سمت راست همان Welcome VS Code ماند:</strong> روی نام فایل کلیک نشده؛ روی فضای خالی ستون کلیک کرده‌ای.</p>
</li>
<li>
<p><strong>یک کلیک روی <code>+</code> سمت راست همان فایل</strong> (وقتی نشانگر روی ردیف است ظاهر می‌شود). معادل <code>git add</code>.<br />
<strong>باید ببینی:</strong> فایل از <strong>Changes</strong> به <strong>Staged Changes</strong> می‌پرد.<br />
<strong>اگر <code>+</code> نبود:</strong> نشانگر را روی ردیف فایل ببر. در بعضی تم‌ها <code>+</code> فقط hover است. یا Palette → <code>Git: Stage Changes</code>.</p>
</li>
<li>
<p><strong>یک کلیک داخل جعبهٔ Message</strong> و بنویس مثلاً <code>feat(auth): add JWT refresh flow</code>.<br />
<strong>اگر جعبه غیرفعال است:</strong> هنوز Staged نداری و Smart Commit خاموش است — مرحلهٔ ۴ را بزن. یا فوکوس روی ادیتور است.</p>
</li>
<li>
<p><strong><code>Ctrl+Enter</code></strong> (مک: <code>Cmd+Enter</code>) <strong>یا</strong> یک کلیک روی دکمهٔ <strong>Commit</strong>.<br />
<strong>باید ببینی:</strong> لیست خالی می‌شود، دکمه ممکن است به Sync/Publish عوض شود، نوار وضعیت <code>↑1</code> بگیرد اگر remote داری.</p>
</li>
</ol>
<p><strong>اگر کلیک Commit همهٔ فایل‌ها را برد نه فقط یکی:</strong> <code>git.enableSmartCommit</code> روشن است. Settings → این گزینه را Off کن. از این به بعد بدون Stage، دکمه Commit کار نمی‌کند یا هشدار می‌دهد.</p>
<p><strong>اگر خطا Signing failed / secret key:</strong> فصل ۲ — امضا روشن است ولی کلید SSH signing روی این ماشین نیست. موقتاً <code>git.enableCommitSigning</code> را Off کن یا کلید را بساز.</p>
<p><strong>اگر خطا Please tell me who you are:</strong> <code>user.name</code> و <code>user.email</code> ست نشده — فصل ۲.</p>
<h2><span class="hx"><span class="hx-t">📦 Staged در برابر Changes — دو کلیک معکوس</span></span></h2>
<div class="shot zoom">
<img src="/git-github-persian-guide/book/figures/vscode-scm-staged-zoom.png" alt="Staged Changes و Changes جدا"/>
<p class="figcap">شکل ۱۰ب — بالا می‌رود داخل کامیت؛ پایین هنوز نمی‌رود. اگر فقط یک لیست می‌بینی، یا چیزی Stage نکرده‌ای یا Untracked جداست.</p>
</div>

</tr>
</tbody>
</table></div><p><strong>اگر Staged Changes را به‌عنوان عنوان جدا نمی‌بینی:</strong> هنوز <code>+</code> نزدی. با Smart Commit روشن، ممکن است بدون این عنوان هم Commit همه را بگیرد — برای همین خاموشش کردیم.</p>
<p><strong>اگر Discard را زدی و فایل برگشت:</strong> Untracked (<code>U</code>) را Discard کردن یعنی حذف فایل از دیسک. VS Code معمولاً «Are you sure?» می‌پرسد. اگر پرسید و Yes گفتی، از Timeline برگردان (پایین فصل).</p>
<p><strong>اگر Untrackedها ته یک لیست قاطی‌اند نه گروه جدا:</strong> Settings → <code>git.untrackedChanges</code> را بگذار <code>separate</code>.</p>
<h2><span class="hx"><span class="hx-t">🔬 hunk — سه کلیک آبی روی خود diff</span></span></h2>
<p class="keep-next">hunk = چند خط سبز/قرمز پشت‌سرهم. معادل <code>git add -p</code>.</p>
<div class="shot zoom">
<img src="/git-github-persian-guide/book/figures/vscode-scm-hunk-zoom.png" alt="Stage Selected Ranges روی diff"/>
<p class="figcap">شکل ۱۰پ — این سه لینک آبی فقط وقتی فایل را از Changes باز کرده باشی بالای hunk ظاهر می‌شوند.</p>
</div>
<ol>
<li>در Changes <strong>یک کلیک</strong> روی فایل.</li>
<li>در diff، خطوطی که می‌خواهی را با ماوس رنگ کن (یا هیچی انتخاب نکن اگر کل hunk را می‌خواهی).</li>
<li><strong>یک کلیک</strong> روی یکی از سه لینک آبی بالای hunk:
<ul>
<li><strong>Stage Change</strong> = کل این hunk</li>
<li><strong>Stage Selected Ranges</strong> = فقط خطوط انتخاب‌شده</li>
<li><strong>Discard Change</strong> = همین hunk از روی دیسک برگردد</li>
</ul>
</li>
</ol>
<p><strong>باید ببینی:</strong> اگر فقط بخشی Stage شد، فایل هم در Staged می‌ماند هم در Changes (حرف گاهی <code>M</code> دو جا). این درست است.</p>
<p><strong>اگر لینک آبی نبود:</strong></p>
<ul>
<li>diff را از Timeline باز کرده‌ای نه از Changes — ببند، از Source Control روی فایل کلیک کن.</li>
<li>روی نمای پیش‌نمایش Markdown هستی نه متن — روی تب فایل خام کلیک کن.</li>
<li>تنظیم <code>diffEditor.renderSideBySide</code> فرق ندارد؛ لینک‌ها باید باشند. VS Code را به‌روز کن.</li>
</ul>

<h2><span class="hx"><span class="hx-t">🧪 تمرین — هر کدام را تا «باید ببینی» پیش برو</span></span></h2>
<p><strong>تمرین ۱.</strong> پوشهٔ خالی Open Folder → باید Initialize ببینی → کلیک Initialize → <code>README.md</code> بساز و Save → باید U در Changes → <code>+</code> → Message <code>docs: add readme</code> → Ctrl+Enter → باید لیست خالی شود.</p>
<p><strong>تمرین ۲.</strong> سه فایل را Save کن → فقط روی یکی <code>+</code> → Commit → باید دو فایل در Changes مانده باشد. اگر هر سه رفتند، Smart Commit را Off کن و تمرین را تکرار کن.</p>
<p><strong>تمرین ۳.</strong> یک فایل را چند خط عوض کن → از Changes باز کن → فقط بعضی خط‌ها را Stage Selected Ranges بزن → باید فایل هم بالا هم پایین باشد.</p>
<p><strong>تمرین ۴.</strong> Discard یک <code>M</code> → از Timeline برگردان.</p>
<div class="callout callout-interview"><div class="callout-title">سؤالات مصاحبه (با پاسخ)</div>
<p><strong>Junior — چرا Save کافی نیست؟</strong> Save فقط فایل روی دیسک را عوض می‌کند. تاریخچه با کلیک Commit ساخته می‌شود.</p>
<p><strong>Mid — چرا مال من دکمه Commit است و در عکس Sync؟</strong> چون تو تغییر ذخیره‌شده داری و عکس کتاب Working Tree تمیز + origin جلوتر را نشان می‌دهد. دکمه بر اساس وضعیت عوض می‌شود.</p>
<p><strong>Senior — Publish to GitHub دقیقاً بعد از چند کلیک چه می‌سازد؟</strong> ریپو، <code>origin</code>، و <code>push -u</code>. بدون Sign in، همان کلیک پنجرهٔ ورود باز می‌کند نه خطا.</p>
