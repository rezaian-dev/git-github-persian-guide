1a:T59a8,<p class="lead">Graph، شاخه، Sync، تعارض، rebase و PR همه از همان Ctrl+Shift+G می‌آیند. مثل فصل ۱۰: هر کار یعنی چند کلیک مشخص، چه باید ببینی، و اگر مال تو فرق داشت یعنی چه.</p>
  <h2><span class="hx"><span class="hx-t">🎯 اهداف یادگیری</span></span></h2>
<ul>
<li>Graph را با کلیک باز کنی و از راست‌کلیک روی کامیت نترسی</li>
<li>Fetch / Pull / Push / Sync را از روی منو جدا بزنی و بدانی چرا دکمهٔ تو با کتاب یکی نیست</li>
<li>تعارض و rebase را تا آخرین کلیک (Continue یا Abort) تمام کنی</li>
<li>اگر Graph، Incoming یا افزونهٔ PR نبود، علت را بدانی</li>
</ul>
<h2><span class="hx"><span class="hx-t">📈 Graph — باز کردن و راست‌کلیک</span></span></h2>
<p><strong>کلیک‌ها برای باز شدن:</strong></p>
<ol>
<li><code>Ctrl+Shift+G</code>.</li>
<li>ته ستون Source Control روی <strong>Graph</strong> یک کلیک (اگر <code>&gt;</code> دیدی، همان را باز کن).</li>
<li class="keep-next">اگر Graph نبود: <code>Ctrl+Shift+P</code> → <code>Git: View History</code> → Enter.</li>
</ol>

</div>

<p class="keep-next"><strong>کلیک ۱:</strong> پایین-چپ پنجره، روی <strong>نام شاخه</strong> (مثلاً <code>main</code>).<br />
<strong>باید ببینی:</strong> فهرست بالا وسط ادیتور (Quick Pick).</p>
<div class="shot">
<img src="/git-github-persian-guide/book/figures/vscode-branch-picker.png" alt="انتخاب شاخه در نوار وضعیت VS Code"/>
<p class="figcap">شکل ۱۱ب — اگر این فهرست نیامد، روی نام شاخه کلیک نشده یا Git پیدا نشده.</p>
</div>
<p><strong>کلیک ۲ — تعویض:</strong> روی نام شاخهٔ دیگر.<br />
<strong>باید ببینی:</strong> نوار وضعیت همان نام را می‌گیرد؛ فایل‌های ادیتور عوض می‌شوند.</p>
<p><strong>اگر خطا Your local changes would be overwritten:</strong> تغییرات ذخیره‌شده داری. اول Commit یا Stash (منوی <code>···</code> → Stash)، بعد دوباره نام شاخه را کلیک کن.</p>
<p class="keep-next"><strong>کلیک ۲ — ساختن:</strong> روی <code>+ Create new branch from...</code> → یک کلیک روی پایه‌ای که می‌خواهی (<code>main</code>) → نام را تایپ کن مثلاً <code>feat/auth</code> → Enter.</p>
<div class="shot">
<img src="/git-github-persian-guide/book/figures/vscode-create-branch.png" alt="ساخت شاخه از Command Palette"/>
<p class="figcap">شکل ۱۱پ — همین کار از Palette با Git: Create Branch from... هم می‌شود.</p>
</div>
<p><strong>کلیک Publish Branch:</strong> در همان فهرست یا روی دکمهٔ ابری نوار وضعیت. اولین push است (<code>-u</code>).</p>
<p><strong>اگر Publish می‌خواهد وارد GitHub شوی:</strong> Accounts پایین Activity Bar → Sign in. بدون origin، دکمهٔ اصلی پنل به‌جای Sync می‌ماند Publish.</p>
<p><strong>اگر شاخهٔ جدید در فهرست نیست:</strong> هنوز Enter ساختن را نزدی، یا <code>refresh</code> لازم است: <code>···</code> → Refresh.</p>

</tr>

<td>Push</td>
<td>↑ صفر شود</td>
<td>rejected = کسی push کرده؛ Fetch کن نه Force</td>
</tr>
<tr>
<td>Sync</td>
<td>ترکیب pull/push</td>
<td>اگر confirmSync روشن باشد یک Yes اضافه می‌پرسد — این «خراب بودن» نیست</td>
</tr>
<tr>
<td>Stash (Include Untracked)</td>
<td>Changes خالی می‌شود</td>
<td>بدون Include، فایل‌های U می‌مانند و switch شکست می‌خورد</td>
</tr>
<tr>
<td>Undo Last Commit</td>
<td>فایل‌ها برمی‌گردند به Staged</td>
<td>اگر push کرده باشی، بعداً Push rejected می‌شود</td>
</tr>
<tr>
<td>Discard All Changes</td>
<td>همهٔ فایل‌های M از لیست می‌روند</td>
<td>پنجرهٔ Are you sure؟ — Yes یعنی از دست رفتن کار ذخیره‌نشده</td>
</tr>
</tbody>
</table></div><p>نوار وضعیت <code>↑1 ↓2</code> یعنی ۱ کامیت برای push و ۲ برای pull. <strong>عدد تو با کتاب یکی نمی‌شود</strong> و نباید بشود.</p>
<h2><span class="hx"><span class="hx-t">💥 تعارض — از حرف C تا Commit (merge)</span></span></h2>
<p>تعارض فقط بعد از Merge / Pull / Cherry-pick / Rebase می‌آید. اگر هیچ‌کدام را نزدی و C دیدی، احتمالاً merge ناتمام قبلی مانده: Palette → <code>Git: Abort Merge</code>.</p>
<p class="keep-next"><strong>باید ببینی:</strong> در Source Control عنوان <strong>Merge Changes</strong> و فایل با حرف <strong>C</strong>. دکمهٔ اصلی ممکن است بشود <strong>Accept Merge</strong> / <strong>Commit (merge)</strong>.</p>
<div class="shot zoom">
<img src="/git-github-persian-guide/book/figures/vscode-scm-conflict-zoom.png" alt="تعارض در Source Control و ادیتور"/>
<p class="figcap">شکل ۱۱ث — نوار آبی چهار فرمان فقط روی فایل C بازشده از Source Control است.</p>
</div>
<p><strong>کلیک‌ها:</strong></p>
<ol>
<li><strong>یک کلیک</strong> روی فایل C.</li>
<li>بالای بلوک قرمز/سبز، <strong>یک کلیک</strong> روی یکی از:
<ul>
<li><strong>Accept Current Change</strong> = نسخهٔ شاخه‌ای که روی آن بودی (<code>HEAD</code> / Ours)</li>
<li><strong>Accept Incoming Change</strong> = نسخه‌ای که داشتی وارد می‌کردی (Theirs)</li>
<li><strong>Accept Both Changes</strong> = هر دو پشت‌سرهم؛ بعد خودت ویرایش کن</li>
<li><strong>Compare Changes</strong> = دو ستون</li>
</ul>
</li>
<li><code>Ctrl+S</code>.</li>
<li><strong>یک کلیک روی <code>+</code></strong> همان فایل (Stage). حرف C باید برود.</li>
<li><strong>یک کلیک روی Commit (merge)</strong> یا Ctrl+Enter با پیام پیش‌فرض merge.</li>
</ol>
<p><strong>اگر نوار Accept نبود:</strong> Palette → <code>Merge Conflict: Open Merge Editor</code> — سه ستون Incoming / Current / Result. Result را درست کن → <strong>Accept Merge</strong>.</p>
<p><strong>اگر هنوز C می‌ماند:</strong> Save و Stage را نزدی. یا چند تعارض در همان فایل است — همه را Accept کن.</p>
<p><strong>پشیمانی قبل از مرحلهٔ ۵:</strong> Palette → <code>Git: Abort Merge</code>. بعد از Commit دیگر abort نیست؛ باید revert.</p>
<h2><span class="hx"><span class="hx-t">🔁 Rebase ناتمام — نوار زرد را تا انتها دنبال کن</span></span></h2>
<p>بعد از <strong>Pull (Rebase)</strong> یا <code>Git: Rebase Branch...</code> اگر تعارض باشد:</p>
<p class="keep-next"><strong>باید ببینی:</strong> در پنل «Rebase in progress»، در بالا ادیتور نوار زرد، دکمه‌های Continue / Abort.</p>
<div class="shot zoom">
<img src="/git-github-persian-guide/book/figures/vscode-scm-rebase-zoom.png" alt="Rebase in progress در Source Control"/>
<p class="figcap">شکل ۱۱ج — تا این نوار هست، دکمهٔ معمولی Commit را نزن. VS Code عمداً کامیت عادی را قفل یا گمراه‌کننده می‌کند.</p>
</div>
<p><strong>کلیک‌ها:</strong></p>
<ol>
<li>فایل C را مثل تعارض حل کن → Save → <code>+</code> (Stage).</li>
<li><strong>یک کلیک Continue</strong> (= <code>git rebase --continue</code>).</li>
<li>اگر تعارض بعدی آمد، ۱ و ۲ را تکرار کن تا نوار زرد برود.</li>
</ol>
<p><strong>اگر Continue خاکستری است:</strong> هنوز همهٔ فایل‌های C را Stage نکرده‌ای، یا Message rebase خالی است — جعبهٔ Message را خالی نگذار.</p>
<p><strong>پشیمانی:</strong> یک کلیک <strong>Abort</strong>. همه چیز برمی‌گردد به قبل از rebase.</p>
<p><strong>اگر وسط rebase VS Code را بستی و باز کردی:</strong> نوار زرد باید برگردد. اگر نماند، Palette → <code>Git: Continue Rebase</code> یا <code>Abort Rebase</code>.</p>
<h2><span class="hx"><span class="hx-t">📚 چند مخزن در یک پنجره</span></span></h2>
<p><strong>کلیک‌ها:</strong> <code>File → Add Folder to Workspace</code> → پوشهٔ دوم که خودش <code>.git</code> دارد.</p>
<p class="keep-next"><strong>باید ببینی:</strong> در Source Control چند عنوان Repository. یک کلیک روی عنوان، آن مخزن را جمع/باز می‌کند.</p>
<div class="shot zoom">
<img src="/git-github-persian-guide/book/figures/vscode-scm-multirepo-zoom.png" alt="چند مخزن در Source Control"/>
<p class="figcap">شکل ۱۱چ — اگر فقط یکی می‌بینی، پوشهٔ دوم Git ندارد یا هنوز Add Folder نکرده‌ای.</p>
</div>
<p><strong>اگر Commit روی مخزن غلط نشست:</strong> عنوان همان Repository را باز کن، بعد Message را بزن. VS Code روی مخزن «فعال» کامیت می‌کند.</p>
<p>worktree: در ترمینال <code>git worktree add -b hotfix/500 ../hotfix main</code> بعد <code>File → Add Folder</code> روی <code>../hotfix</code>. یک شاخه در دو worktree هم‌زمان باز نمی‌شود — پیام خطا را با Stash یا عوض کردن شاخه حل کن.</p>
<h2><span class="hx"><span class="hx-t">📬 Pull Request — افزونه، نه خود Git توکار</span></span></h2>
<p>Source Control توکار PR نمی‌سازد. باید افزونهٔ <strong>GitHub Pull Requests</strong> نصب باشد.</p>
<p><strong>کلیک نصب:</strong> Activity Bar آیکون Extensions (یا <code>Ctrl+Shift+X</code>) → جست‌وجو <code>GitHub Pull Requests</code> → Install → Accounts پایین Activity Bar → <strong>Sign in to GitHub</strong> → مرورگر Allow.</p>
<p class="keep-next"><strong>اگر آیکون GitHub در Activity Bar نیامد:</strong> افزونه نصب نشده یا غیرفعال است. View → Appearance → Activity Bar را چک کن.</p>
<div class="shot">
<img src="/git-github-persian-guide/book/figures/vscode-pr-ext.png" alt="بررسی Pull Request داخل VS Code"/>
<p class="figcap">شکل ۱۲ — این نما مال افزونه است نه ستون Git. اگر ندیدی، Sign in نشده.</p>
</div>
<p><strong>ساخت PR از شاخهٔ فعلی:</strong></p>
<ol>
<li>اول Push / Publish Branch از Source Control (وگرنه GitHub شاخه را ندارد).</li>
<li><code>Ctrl+Shift+P</code> → <code>GitHub Pull Requests: Create Pull Request</code>.</li>
<li>عنوان و پایه (<code>main</code>) را تأیید کن → Create.</li>
</ol>
<p><strong>اگر Create خطا می‌دهد no upstream:</strong> Publish Branch را جا انداختی.</p>
<p><strong>ریویو:</strong> آیکون GitHub → یک کلیک روی PR → Checkout → در Files Changed روی خط کلیک → کامنت → Approve.</p>
<p><strong>اگر Checkout PR فایل‌های تو را overwrite می‌کند:</strong> اول Commit یا Stash از ستون Source Control.</p>
