<ol>

<li>Require a pull request (۱–۲ Approve)</li>

<li>Require signed commits (اگر تیم آماده است)</li>
<li>Dismiss stale reviews on new push</li>
<li>Require review from Code Owners</li>

<p>آخرین قانونِ مطابق برنده است. بدون Ruleset «code owners»، این فایل فقط مستندات است.</p>
<h2><span class="hx"><span class="hx-t">🌍 Environments</span></span></h2>
<p class="keep-next">برای Actions:</p>
<ul>
<li><code>staging</code> — بدون دروازه</li>
<li><code>production</code> — required reviewers + wait timer + restricted secrets</li>
</ul>
<p>حتی اگر شاخه آزاد باشد، deploy به production بدون Approve انسانی نمی‌رود. از ۲۰۲۵ <strong>Immutable Releases</strong> هم دارایی و تگ عرضه را قفل می‌کند.</p>
<h2><span class="hx"><span class="hx-t">🖥️ اثر روی VS Code</span></span></h2>
<p class="keep-next">اگر مستقیم روی <code>main</code> کامیت کنی:</p>
<ul>
<li>محلی: <code>git.branchProtection</code> هشدار می‌دهد</li>
<li>push: سرور رد می‌کند با پیام Ruleset</li>
</ul>
<p>پیام خطا را بخوان؛ معمولاً لینک به کدام rule است.</p>
<div class="callout callout-tip"><div class="callout-title">Repository ruleset برای تگ</div>
<p><code>v*</code> را قفل کن تا کسی تگ نسخه را جابه‌جا نکند. همراه Immutable Releases، عرضه قابل‌اثبات می‌شود.</p>
</div>
<div class="callout callout-interview"><div class="callout-title">سؤالات مصاحبه (با پاسخ)</div>
<p><strong>Mid — linear history یعنی چه؟</strong> فقط fast-forward؛ merge commit روی main ممنوع. با squash یا rebase merge جور است.</p>
<p><strong>Senior — bypass چه کسی باید داشته باشد؟</strong> فقط bot حادثه و چند admin. اگر همه bypass دارند، سیاست تئاتر است.</p>
</div>
