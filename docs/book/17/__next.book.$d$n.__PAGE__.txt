gh<span style="color: #F8F8F2"> </span>pr<span style="color: #F8F8F2"> </span>create<span style="color: #F8F8F2"> </span>--draft<span style="color: #F8F8F2"> </span>--fill<span style="color: #F8F8F2"> </span>--reviewer<span style="color: #F8F8F2"> </span>teammate

<div class="cols">
<div class="col"><div class="col-title">🖥️ افزونه GitHub Pull Requests</div>
<ol>
<li>بعد از Push، نوار آبی <em>Create Pull Request</em></li>
<li>یا Activity Bar → آیکون GitHub → <em>Create Pull Request</em></li>
<li>Draft را تیک بزن، Reviewer انتخاب کن</li>
<li><em>Checkout</em> روی PR دیگران برای تست محلی</li>
<li>Files Changed → کامنت اینلاین → <strong>Submit Review</strong></li>
<li>Merge از همان پنل (Squash/Merge/Rebase طبق تنظیم تیم)</li>
</ol>
</div>
<div class="col"><div class="col-title">⌨️ Terminal + gh</div>
<p><code>git push -u origin HEAD</code>
<code>gh pr create --draft --fill</code>
<code>gh pr checkout 42</code>
<code>gh pr merge 42 --squash</code></p>
</div>

<p class="keep-next">بدنهٔ خوب:</p>

<li><strong>چه</strong> عوض شد — در سطح محصول نه خط‌به‌خط</li>
<li><strong>چگونه تست شد</strong></li>
<li>اسکرین شات اگر UI است</li>

<div class="callout callout-tip"><div class="callout-title">اندازه</div>
<p>هدف: زیر ۴۰۰ خط منطقی. اگر بزرگ است، stacked PR یا چند PR متوالی. ریویوکننده خسته Approve دروغین می‌زند.</p>
</div>
<h2><span class="hx"><span class="hx-t">🧪 Checks</span></span></h2>
<p class="keep-next">هر Push روی شاخهٔ PR، Actions را آتش می‌زند (فصل ۲۸). مربع سبز <em>Able to merge</em> یعنی:</p>
<ul>
<li>تعارض با base نیست</li>
<li>بررسی‌های required پاس شده</li>
<li>تعداد Approve کافی است</li>
<li>conversationها resolve شده‌اند (اگر اجباری باشد)</li>
</ul>
<p>در VS Code تب Checks همان وضعیت را نشان می‌دهد.</p>

<h2><span class="hx"><span class="hx-t">🧹 قبل از Review</span></span></h2>
<div class="code"><div class="code-head"><span class="dots"><i></i><i></i><i></i></span><span class="fname">تمیزکاری</span></div><pre>git<span style="color: #F8F8F2"> </span>fetch<span style="color: #F8F8F2"> </span>origin
git<span style="color: #F8F8F2"> </span>rebase<span style="color: #F8F8F2"> </span>origin/main<span style="color: #F8F8F2">          </span><span style="color: #959077"># روی شاخهٔ شخصی</span>
git<span style="color: #F8F8F2"> </span>push<span style="color: #F8F8F2"> </span>--force-with-lease
</pre></div>
<p>تعارض را تو حل کن نه ریویوکننده.</p>
<div class="callout callout-warn"><div class="callout-title">PR به main مستقیم از لپ‌تاپ بدون CI</div>
<p>حتی در پروژهٔ شخصی Actions را روشن کن. حافظه عضله‌ای Production از همین‌جا ساخته می‌شود.</p>
</div>
<div class="callout callout-interview"><div class="callout-title">سؤالات مصاحبه (با پاسخ)</div>
<p><strong>Junior — Draft یعنی چه؟</strong> PR قابل merge نیست تا Ready شود؛ سیگنال «نگاه نکن هنوز».</p>
<p><strong>Mid — چرا force-with-lease بعد از rebase؟</strong> چون rebase هش عوض می‌کند؛ lease جلوی پاک کردن کار همکار روی همان شاخه را می‌گیرد.</p>
<p><strong>Senior — stacked PR؟</strong> زنجیرهٔ PR که هر کدام روی قبلی است؛ نیازمند ابزار (Graphite یا <code>gh</code>) و توافق تیم.</p>
</div>
