5:T2052,<p class="lead">Rebase کامیت‌های شاخهٔ تو را برمی‌دارد و یکی‌یکی روی نوک یک شاخهٔ دیگر دوباره اعمال می‌کند. نتیجه تاریخچهٔ خطی است، ولی هش هر کامیت عوض می‌شود. فقط روی شاخه‌ای که دیگران از آن استفاده نمی‌کنند این کار را بکن.</p>
  <h2><span class="hx"><span class="hx-t">🎯 اهداف یادگیری</span></span></h2>
<ul>
<li>rebase را به‌عنوان «کامیت‌ها را روی پایهٔ جدید دوباره پخش کن» توضیح دهی</li>
<li><code>rebase -i</code> را برای squash و reword به کار ببری</li>
<li><code>--autosquash</code> و <code>fixup!</code> را بلد باشی</li>
<li class="keep-next">قانون طلایی را هرگز نشکنی</li>
</ul>
<div class="diagram">

<p class="figcap">شکل ۱۶ — rebase کامیت‌های جدید می‌سازد (D′ و E′)؛ هش عوض می‌شود.</p>
</div>
<h2><span class="hx"><span class="hx-t">🧠 rebase دقیقاً چه می‌کند؟</span></span></h2>
<p class="keep-next">Git هر کامیت شاخهٔ تو را که در <code>main</code> نیست برمی‌دارد، <code>main</code> را HEAD می‌کند، و وصله‌ها را یکی‌یکی اعمال می‌کند. نتیجه: تاریخچهٔ خطی. هزینه: هویت جدید برای هر کامیت.</p>
<div class="code"><div class="code-head"><span class="dots"><i></i><i></i><i></i></span><span class="fname">به‌روز کردن شاخهٔ شخصی</span></div><pre>git<span style="color: #F8F8F2"> </span>fetch<span style="color: #F8F8F2"> </span>origin
git<span style="color: #F8F8F2"> </span>switch<span style="color: #F8F8F2"> </span>feat/auth
git<span style="color: #F8F8F2"> </span>rebase<span style="color: #F8F8F2"> </span>origin/main
git<span style="color: #F8F8F2"> </span>push<span style="color: #F8F8F2"> </span>--force-with-lease
</pre></div>
<div class="cols">
<div class="col"><div class="col-title">🖥️ VS Code Git</div>
<ul>
<li><code>...</code> → <strong>Pull (Rebase)</strong> برای به‌روز کردن شاخه</li>
<li>Palette: <code>Git: Rebase Branch...</code> → <code>origin/main</code></li>
<li>تعارض: Merge Editor → Stage → <code>Git: Rebase Continue</code></li>
<li>نوار زرد بالای ادیتور یعنی rebase ناتمام است — کامیت عادی نزن</li>
<li><code>Git: Rebase Abort</code> برای پشیمانی</li>
</ul>
</div>
<div class="col"><div class="col-title">⌨️ Terminal</div>
<p><code>git fetch origin</code>
<code>git rebase origin/main</code>
<code>git rebase --continue</code>
<code>git rebase --abort</code>
<code>git push --force-with-lease</code></p>
</div>
</div>

<div class="callout callout-danger"><div class="callout-title">هرگز rebase روی کامیت عمومی</div>
<p>اگر <code>origin/main</code> یا شاخه‌ای که همکارت checkout کرده شامل آن هش‌هاست، rebase = دو تاریخچهٔ موازی و force-push جنگی.</p>
</div>
<h2><span class="hx"><span class="hx-t">⚡ fixup و autosquash</span></span></h2>
<div class="code"><div class="code-head"><span class="dots"><i></i><i></i><i></i></span><span class="fname">بعد از ریویو، بدون کامیت «address comments»</span></div><pre>git<span style="color: #F8F8F2"> </span>commit<span style="color: #F8F8F2"> </span>--fixup<span style="color: #F8F8F2"> </span>a11
git<span style="color: #F8F8F2"> </span>rebase<span style="color: #F8F8F2"> </span>-i<span style="color: #F8F8F2"> </span>--autosquash<span style="color: #F8F8F2"> </span>origin/main
</pre></div>
<p><code>--fixup</code> پیامی مثل <code>fixup! feat: add login form</code> می‌سازد؛ autosquash آن را زیر هدف می‌چسباند. در Git جدید <code>git commit --squash</code> هم هست.</p>
<p>از Git ۲.۳۸+ پرچم <code>--update-refs</code> شاخه‌های محلی دیگری که به کامیت‌های بازنویسی‌شده اشاره می‌کردند را هم حرکت می‌دهد — نجات از شاخه‌های یتیم.</p>
<h2><span class="hx"><span class="hx-t">🧩 تعارض وسط rebase</span></span></h2>
<div class="code"><div class="code-head"><span class="dots"><i></i><i></i><i></i></span><span class="fname">نجات</span></div><pre><span style="color: #959077"># فایل را در VS Code حل و Stage کن</span>
git<span style="color: #F8F8F2"> </span>rebase<span style="color: #F8F8F2"> </span>--continue
git<span style="color: #F8F8F2"> </span>rebase<span style="color: #F8F8F2"> </span>--abort<span style="color: #F8F8F2">          </span><span style="color: #959077"># پشیمانی کامل</span>
git<span style="color: #F8F8F2"> </span>rebase<span style="color: #F8F8F2"> </span>--skip<span style="color: #F8F8F2">           </span><span style="color: #959077"># این وصله را دور بینداز — خطرناک</span>
</pre></div>
<p><code>rerere</code> (فصل ۲۴) تعارض تکراری را به خاطر می‌سپارد.</p>
<div class="callout callout-tip"><div class="callout-title">VS Code</div>
<p>وضعیت rebase را نوار زرد بالای ادیتور نشان می‌دهد. Merge Editor همان UI تعارض فصل ۷ است. تا نوار زرد هست، کامیت عادی نزن.</p>
</div>
<div class="callout callout-interview"><div class="callout-title">سؤالات مصاحبه (با پاسخ)</div>
<p><strong>Mid — چرا PR بعد از rebase «جدید» به نظر می‌رسد؟</strong> چون هش عوض شده؛ GitHub فایل‌ها را مقایسه می‌کند نه هش را. Force-with-lease لازم است.</p>
<p><strong>Senior — rebase در برابر merge برای به‌روز کردن شاخه؟</strong> rebase تاریخچهٔ PR را خطی و خوانا می‌کند؛ merge یک گره همگام‌سازی اضافه می‌کند. تیم باید یکی را انتخاب کند.</p>
</div>
<h2><span class="hx"><span class="hx-t">✅ چک‌لیست فهم</span></span></h2>

<li><code>--abort</code> عضله‌ای شده</li>
<li>force خام نمی‌زنی</li>
</ul>
