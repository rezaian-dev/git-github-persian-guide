5:T10ca,<p class="lead">Issue برای ثبت باگ و کار است، Project برای برد کارهای تیم، Discussion برای سؤال باز. این‌ها روی GitHub زندگی می‌کنند، نه داخل پوشهٔ <code>.git</code>.</p>
  <h2><span class="hx"><span class="hx-t">🎯 اهداف یادگیری</span></span></h2>
<ul>
<li>Issue خوب بنویسی (بازتولید، انتظار، واقعیت)</li>
<li>برچسب، مایل‌استون و قالب را بچینی</li>
<li>GitHub Projects v2 را به PR وصل کنی</li>
<li>بدانی Discussion کی بهتر از Issue است</li>
</ul>
<h2><span class="hx"><span class="hx-t">🐞 آناتومی Issue</span></span></h2>
<div class="code"><div class="code-head"><span class="dots"><i></i><i></i><i></i></span><span class="fname">.github/ISSUE_TEMPLATE/bug.yml — ایده</span></div><pre><span style="color: #959077">## شرح</span>
<span style="color: #959077">## گام بازتولید</span>
<span style="color: #959077">## انتظار</span>
<span style="color: #959077">## واقعیت</span>
<span style="color: #959077">## نسخه / محیط</span>
<span style="color: #959077">## لاگ</span>
</pre></div>
<p>قانون: <strong>یک Issue = یک مشکل</strong>. «همچنین این را هم درست کنید» را Issue جدا کن و لینک بده (<code>blocked by #12</code>).</p>
<p class="keep-next">کلیدواژه‌های جادویی در PR:</p>
<ul>
<li><code>Fixes #12</code> — با merge، Issue بسته می‌شود</li>
<li><code>Refs #12</code> — فقط لینک</li>
</ul>
<h2><span class="hx"><span class="hx-t">🏷️ لیبل‌های مفید</span></span></h2>
<p><code>bug</code>، <code>feat</code>، <code>docs</code>، <code>good first issue</code>، <code>help wanted</code>، <code>security</code>، <code>wontfix</code>. رنگ مهم نیست؛ قرارداد مهم است.</p>
<h2><span class="hx"><span class="hx-t">📊 Projects v2</span></span></h2>
<p class="keep-next">Projects جدید روی جدول/بورد/زمان‌بندی است و فیلد سفارشی دارد (تخمین، ناحیه). می‌توانی با Actions وقتی PR باز شد کارت بسازی.</p>
<div class="code"><div class="code-head"><span class="dots"><i></i><i></i><i></i></span><span class="fname">ایدهٔ اتوماسیون</span></div><pre><span style="color: #959077"># در workflow: gh project item-add</span>
</pre></div>
<p>در سازمان‌ها Projects جایگزین Trello داخلی می‌شود چون به commit و PR وصل است.</p>
