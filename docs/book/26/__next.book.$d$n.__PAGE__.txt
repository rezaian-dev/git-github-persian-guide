<h2><span class="hx"><span class="hx-t">✅ Verified یعنی چه؟</span></span></h2>
<p class="keep-next">GitHub کامیت را Verified می‌گذارد اگر:</p>
<ol>
<li>با کلید ثبت‌شده (SSH یا GPG یا S/MIME) امضا شده باشد</li>
<li>نویسنده با حساب منطبق باشد</li>
</ol>
<p class="keep-next">در فصل ۲ SSH signing را چیدیم. برای تگ انتشار:</p>
<div class="code"><div class="code-head"><span class="dots"><i></i><i></i><i></i></span><span class="fname">تگ امضاشده</span></div><pre>git<span style="color: #F8F8F2"> </span>tag<span style="color: #F8F8F2"> </span>-s<span style="color: #F8F8F2"> </span>v1.0.0<span style="color: #F8F8F2"> </span>-m<span style="color: #F8F8F2"> </span><span style="color: #E6DB74">&quot;Git GitHub Persian Guide 1.0.0&quot;</span>
git<span style="color: #F8F8F2"> </span>push<span style="color: #F8F8F2"> </span>origin<span style="color: #F8F8F2"> </span>v1.0.0
</pre></div>
<p>Ruleset می‌تواند <em>Require signed commits</em> را روی <code>main</code> اجباری کند.</p>
<h2><span class="hx"><span class="hx-t">🔐 حساب GitHub در ۲۰۲۶</span></span></h2>
<p class="keep-next">حداقل‌ها:</p>
<ul>
<li><strong>Passkey / 2FA</strong> اجباری برای orgهای جدی</li>
<li><strong>Sudo mode</strong> برای کارهای حساس</li>
<li><strong>Session</strong> را در دستگاه عمومی قطع کن</li>
<li><strong>SSH keys</strong> را سالی یک‌بار مرور کن</li>
<li><strong>Authorized applications</strong> OAuth را هرس کن</li>
<li class="keep-next"><strong>Fine-grained PAT</strong> به‌جای classic، با انقضای کوتاه و دسترسی ریپوی مشخص</li>
</ul>
<div class="code"><div class="code-head"><span class="dots"><i></i><i></i><i></i></span><span class="fname">PAT را در Git ذخیره نکن</span></div><pre><span style="color: #959077"># SSH ترجیح این کتاب است</span>
gh<span style="color: #F8F8F2"> </span>auth<span style="color: #F8F8F2"> </span>token<span style="color: #F8F8F2">    </span><span style="color: #959077"># نشان بده؛ در فایل پروژه نگذار</span>
</pre></div>
<div class="callout callout-danger"><div class="callout-title">PAT داخل ریپو</div>
<p>Secret scanning گیت‌هاب بسیاری از توکن‌ها را push را رد می‌کند. اگر رد نشد، فوراً revoke کن — rotate، نه فقط delete فایل.</p>
</div>
<h2><span class="hx"><span class="hx-t">🧹 اگر secret وارد تاریخچه شد</span></span></h2>
<div class="code"><div class="code-head"><span class="dots"><i></i><i></i><i></i></span><span class="fname">فایل را از HEAD برداشتن کافی نیست</span></div><pre>git<span style="color: #F8F8F2"> </span>rm<span style="color: #F8F8F2"> </span>--cached<span style="color: #F8F8F2"> </span>.env

<span style="color: #959077"># تاریخچه هنوز راز را دارد!</span>
</pre></div>
<p class="keep-next">برای پاک کردن تاریخچه:</p>
<ul>
<li><code>git filter-repo</code> (جانشین filter-branch)</li>
<li>BFG Repo-Cleaner</li>
<li>GitHub: <em>Remove sensitive data</em> + <strong>حتماً توکن را revoke</strong></li>
</ul>
<p>Force-push همهٔ کلون‌ها را باطل می‌کند. تیم باید دوباره clone کند.</p>
<p>در VS Code هیچ دکمه‌ای «پاک کردن تاریخچه» ندارد — و نباید داشته باشد.</p>
<h2><span class="hx"><span class="hx-t">🧑💻 VS Code و هویت</span></span></h2>
<ul>
<li>Accounts → GitHub sign in (برای PR و Copilot)</li>
<li><code>git.enableCommitSigning</code></li>
<li>هرگز token را در <code>settings.json</code> نگذار</li>
</ul>
<div class="callout callout-interview"><div class="callout-title">سؤالات مصاحبه (با پاسخ)</div>
<p><strong>Junior — Verified زرد/خاکستری؟</strong> کلید با حساب یکی نیست یا فرمت امضا اشتباه است.</p>
<p><strong>Mid — fine-grained در برابر classic PAT؟</strong> محدود به ریپو، انقضا، permission جداگانه؛ classic practically root است.</p>
<p><strong>Senior — چرا revoke مهم‌تر از filter-repo است؟</strong> مهاجم ممکن است از قبل clone کرده باشد. پاک کردن تاریخچهٔ عمومی جلوی استفادهٔ توکن زنده را نمی‌گیرد.</p>
</div>
