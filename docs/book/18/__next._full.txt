1a:T10e9,<p class="lead">Code Review یعنی قبل از Merge، حداقل یک نفر دیگر diff را بخواند. هدف پیدا کردن باگ و انتقال دانش است، نه خرد کردن نویسنده.</p>
  <h2><span class="hx"><span class="hx-t">🎯 اهداف یادگیری</span></span></h2>
<ul>
<li>نظر را روی <em>کد</em> بگذاری نه روی <em>آدم</em></li>
<li>از Prefixهای متعارف استفاده کنی</li>
<li>Review در VS Code را Submit کنی نه فقط کامنت محلی</li>
<li>بدانی Approve مسئولیت است</li>
</ul>
<h2><span class="hx"><span class="hx-t">🧭 اصول</span></span></h2>
<ol>
<li><strong>نیت نویسنده را فرض خیر بگذار</strong></li>
<li><strong>سؤال بپرس قبل از حکم</strong> («اینجا race ممکن است؟» نه «این غلط است»)</li>
<li><strong>nit را برچسب بزن</strong> تا با blocker قاطی نشود</li>
<li><strong>تحسین کن</strong> — الگوی خوب را تکرارپذیر کن</li>
<li><strong>خارج از scope را Issue کن</strong> نه گروگان PR</li>
</ol>
<p class="keep-next">پیشوندهای رایج:</p>

<h2><span class="hx"><span class="hx-t">🖱️ ریویو در VS Code</span></span></h2>
<ol>
<li>PR را Checkout کن و واقعاً اجرا کن — نه فقط diff</li>
<li>روی خط <em>Add Comment</em> — می‌توانی suggestion بگذاری (<code>```suggestion</code>)</li>
<li>چند کامنت pending بمانند</li>
<li><em>Submit Review</em> با یکی از: Comment / Approve / Request Changes</li>
</ol>
<div class="callout callout-warn"><div class="callout-title">کامنت بدون Submit</div>
<p>Pending فقط روی ماشین توست. نویسنده چیزی نمی‌بیند تا Submit کنی.</p>
</div>
<h2><span class="hx"><span class="hx-t">✅ چک‌لیست نویسنده قبل از درخواست ریویو</span></span></h2>
<div class="checklist">
<ul>
<li>خودت diff را از بالا تا پایین خواندی</li>
<li>فایل debug و <code>.env</code> نیست</li>
<li>تست جدید برای رفتار جدید</li>
<li>CI سبز</li>
<li>توضیحات PR کامل است</li>
</ul>
</div>
<h2><span class="hx"><span class="hx-t">✅ چک‌لیست ریویوکننده</span></span></h2>
<div class="checklist">
<ul>
<li>صحت: آیا باگ منطقی هست؟</li>
<li>امنیت: تزریق، رمز، XSS، secret</li>
<li>طراحی: آیا API پایدار می‌ماند؟</li>
<li>تست: آیا فقدان پوشش هست؟</li>
<li>مشاهده‌پذیری: لاگ و خطا</li>
</ul>
</div>
<div class="callout callout-interview"><div class="callout-title">سؤالات مصاحبه (با پاسخ)</div>

<p><strong>Senior — LGTM بدون نگاه؟</strong> بدهی اعتماد. در حادثه، امضای تو روی تاریخچه است. Ruleset «dismiss stale reviews» را روشن کن تا push جدید Approve کهنه را باطل کند.</p>
